# README.md Modification Rule

The README.md file represents the purpose of existence, the meaning of the project, and the brief description of the most general informations about the project (architecture, installation, build project, features, usage, etc.). It is planned from the very first beginning. Whatever you do when asked to modify this file, do not mistakenly think you have done a large proportion of work—it is just one part of the whole machine. Make sure to check the previous versions of this file to make suitable modifications.

# No Magic Numbers or Strings Rule

Avoid using magic numbers and magic strings in the codebase. Always extract hardcoded values (such as timeout durations, default UUIDs, status labels, etc.) into named constants, enums, or configuration variables to improve readability and maintainability.
